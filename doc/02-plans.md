# 2. 플랜 관리

기획서 하나를 **플랜**이라고 부릅니다. 서비스 하나당 플랜 하나라고 생각하시면 됩니다.

---

## 새로 만들기

홈에서 **`＋ 기획하기`** 를 누르면 6단계 창이 열립니다. **필수는 1단계의 두 칸뿐**이고,
3단계부터는 언제든 `이대로 만들기` 로 끝낼 수 있습니다. 창을 닫아도 쓰던 내용은 남습니다.
처음부터 다시 쓰려면 1단계 오른쪽 위의 `새로 쓰기` 를 누르세요.

### 1단계 — 무엇을 만드나요

| 칸 | 필수 | 예시 |
| --- | --- | --- |
| **서비스 아이디어** | ✅ | 아래 세 줄 형식을 권합니다 |
| **서비스명** | ✅ | `산책메이트` — 가칭이어도 됩니다 |

> **형식은 자유입니다.** "해결할 문제:" 같은 줄 없이 만들고 싶은 서비스를 생각나는 대로 쭉 적으셔도
> 됩니다. AI 는 글 전체를 읽고 문서를 만듭니다. 아래 칩은 빠뜨리기 쉬운 것을 짚어 주는
> **도우미**일 뿐 필수가 아닙니다. 다만 *누가 어떤 불편을 겪는지 · 어떻게 풀어 주는지 ·
> 사용자가 주로 무엇을 하는지* 가 글 어딘가에 들어 있으면 문서가 더 정확해집니다.
>
> ```
> 사진 잘 나오는 명소를 지도에서 찾고, 그 자리에서 AI 가 구도를 잡아 줘서
> 인생샷을 찍은 뒤 앱 커뮤니티에 올리는 앱. 다른 사람이 올린 사진과 위치도 볼 수 있다.
> ```
>
> 이렇게 줄글로 적어도 됩니다. 줄 칩에 ✓ 가 안 붙어도 다음으로 넘어갈 수 있습니다.

정리해서 적고 싶으시면 아이디어 칸 아래의 **`해결할 문제` `해결 방법` `핵심 행동`** 칩을 누르세요. 그 줄이 들어가고,
내용을 채우면 칩에 ✓ 가 붙습니다. 세 줄을 다 채울수록 문서가 정확해집니다.

```
해결할 문제: 혼자 사는 반려인은 함께 산책할 이웃을 찾기 어렵다
해결 방법: 동네와 산책 시간이 맞는 견주를 이어 준다
핵심 행동: 근처 메이트 찾기 → 산책 요청 → 함께 산책 → 후기 남기기
```

**비어 있는 줄 제안** — 한두 줄만 적어도 AI 가 비어 있는 줄에 넣을 후보를 보여 줍니다.
**누른 것만 들어갑니다.** AI 가 쓰신 글을 고쳐 쓰지는 않습니다.

**서비스 구조** — 아이디어를 다 적은 뒤 `서비스 구조 생성하기` 를 누르면 어떤 구조의 서비스인지 추정해 보여 줍니다. 문서의 뼈대가
여기서 정해지니 한 번 확인해 주세요.

| 구조 | 예 |
| --- | --- |
| 🤝 중개·매칭 | 당근, 숨고, 산책 메이트, 장비 대여 |
| 🛒 판매·주문 | 자사몰, 구독 박스 |
| 📅 예약·일정 | 미용실·진료·구장 예약 |
| 💬 커뮤니티 | 동호회, Q&A |
| 🗂️ 팀 업무 도구 | 학원 관리, CRM |
| 📒 개인 기록·관리 | 가계부, 습관 기록 |
| 🎬 콘텐츠·학습 | 온라인 강의, 어학 앱 |
| 🔎 정보 찾기 | 맛집 지도, 병원 찾기 |

- 맞으면 **`맞아요`**, 다르면 **`바꾸기`** 로 고르세요. 확인한 구조는 문서에 **반드시** 반영되고,
  확인하지 않은 추정은 아이디어 설명과 어긋날 때 아이디어를 따릅니다.
- 성격이 둘 섞였으면 `+ 보조 유형` 으로 하나를 더 붙입니다 (예: 과외 앱 = 중개·매칭 + 예약·일정).
- `함께 고려` 에는 위치 정보·대면 만남·미성년 이용·건강 정보·돈·금융 중 해당하는 것이 붙습니다.
  동의 화면이나 제약사항에 들어가니, 해당 없으면 × 로 빼세요.
- 만드는 동안 기다리지 않고 넘어가셔도 됩니다. 늦게 오면 2단계 맨 위에 보입니다. 만든 뒤 아이디어를 고치면 `다시 생성` 을 눌러 주세요.

> 아이디어 칸이 비어 있을 때 보이는 **예시**를 누르면 서비스명과 아이디어가 함께 채워집니다.

창 위의 **문서 깊이** 막대는 답한 만큼 `기본 → 충분 → 상세` 로 차오릅니다. 답할수록 문서가 촘촘해진다는 표시입니다.

### 2단계 — 누구를 위해

| 칸 | 예시 |
| --- | --- |
| 타겟 사용자 | `서울에 사는 20~30대 1인 가구 반려인` |
| 이 기획서를 어디에 쓰시나요? | 최소 출시 범위 / 개발 견적·외주 발주 / 투자·사업계획 / 사내 보고 / 기존 서비스 개편 |
| 주 고객 · 주 연령대 · 얼마나 자주 | 고르기만 하면 됩니다 |
| 플랫폼 | 웹 / 모바일 앱 / 웹＋앱 / 어드민 / 윈도우 앱 |

**용도에 따라 문서에서 꼼꼼히 쓰는 곳이 달라집니다.** 견적용이면 범위 제외·가정·비기능 요구사항을,
투자용이면 성공 지표와 마일스톤을 강조합니다. 10대 이하를 고르면 보호자 동의, 60대 이상이면 큰 글씨와
단순한 흐름이 들어갑니다.

구조가 **중개·매칭이고 제공하는 쪽이 따로 있으면** 타겟 사용자가 `찾는 쪽` · `제공하는 쪽` 두 칸으로 나뉩니다.

### 3단계 — 참고 정보

| 칸 | 예시 |
| --- | --- |
| 참고 서비스 · 다른 점 | `당근마켓` / `동네 인증은 따르고, 채팅 대신 예약으로` |
| **꼭 있어야 할 기능** | 필수(P0)로 들어갑니다 |
| 있으면 좋은 기능 | 우선순위를 낮게 잡습니다 |
| **이번에 만들지 않을 것** | 범위 제외에 그대로 들어갑니다 |
| 기존 자료 붙여넣기 | 회의록·기존 기획서·고객 요청 메일 (앞부분 5,000자) |

> **`이번에 만들지 않을 것` 을 꼭 채우세요.** 개발 견적을 받을 때 가장 많이 다투는 부분입니다.

이번 기획의 **AI 엔진**(기본/고급)도 여기서 고릅니다.

### 4단계 — 몇 가지만 더

고르기만 하면 되는 질문입니다. 모든 서비스에 묻는 6개 뒤에 **1단계 구조에 따라 갈라지는 질문**이 붙습니다.

- 모르겠으면 **`잘 모르겠어요`** 를 누르세요. 비워 두면 AI 가 말없이 추측하지만, 이걸 고르면 AI 가 정하되
  문서에 **"가정: …"** 으로 남겨 나중에 확인할 수 있습니다.
- **`더 자세히 답하기`** 를 펼치면 사용자끼리 대화, 사진·파일 올리기, 외부 연동, 예상 이용자 수를 물을 수 있습니다.

### 5단계 — 확인할 것

AI 가 아이디어를 읽고 이 서비스에만 해당하는 것을 되묻습니다. 정책(기한·한도)과 예외 상황(취소·분쟁)을 우선 묻고,
질문마다 **영역 꼬리표**와 **추천** 보기가 붙습니다.

- **`빈 곳은 추천대로`** — 답하지 않은 질문을 추천 보기로 한 번에 채웁니다.
- **`답한 것에서 더 여쭤보기`** — 답한 것을 실제로 만들려면 무엇을 더 정해야 하는지 꼬리 질문을 한 번 더 받습니다.
  예: "보증금으로 처리" → "보증금 액수는 어떻게 정하나요?"
- 답하지 않은 질문은 버리지 않고 문서에 **가정**으로 남깁니다.

### 6단계 — 이해한 내용

"제가 이해한 게 맞나요?" — 지금까지 받은 것을 7줄(누구의 · 어떤 문제를 · 어떻게 풀고 · 처음 가치를 느끼는 순간 ·
돈은 · 이번에 만들 것 · 만들지 않을 것)로 정리해 보여 줍니다.

- `추정` 표시가 붙은 줄은 직접 말하지 않아 AI 가 채운 것입니다. **틀린 줄은 바로 고치세요.**
- 아래 **가정** 목록은 정하지 않은 것을 어떻게 두고 만들지입니다. 고치거나 × 로 빼거나 더할 수 있습니다.
- 여기서 확인한 요약이 **모든 문서 생성에서 가장 앞섭니다.** 크레딧을 쓰기 전에 오해를 잡는 마지막 기회입니다.

## 플랜 카드 읽는 법

홈의 카드 하나가 기획서 하나입니다.

```
┌─────────────────────────────┐
│ 산책메이트               ⋮  │  ← 서비스명 / 메뉴
│ 동네 산책 친구를 찾아주는 앱  │  ← 한 줄 소개
│                             │
│ [모바일 앱] [산출물 3/5]      │  ← 플랫폼 / 진행률
│ [PRD✓][기능명세서✓][정보구조도✓]│  ← 만들어진 문서
│ [유저 플로우][와이어프레임]     │     (흐린 것은 아직 안 만듦)
│                             │
│ 요구사항 7 · 기능 21 · 화면 23 │  ← 담긴 내용
│ 최종 수정 2시간 전            │
└─────────────────────────────┘
```

카드를 누르면 그 기획서로 들어갑니다.

### ⋮ 메뉴

| 항목 | 하는 일 |
| --- | --- |
| **이름 변경** | 서비스명을 바꿉니다 |
| **복제** | 똑같은 내용으로 하나 더 만듭니다 |
| **JSON 내보내기** | 파일로 저장합니다 (백업용) |
| **삭제** | 완전히 지웁니다 — **되돌릴 수 없습니다** |

> **복제**는 이럴 때 씁니다. 지금 기획서를 크게 바꿔 보고 싶은데 원본도 남기고 싶을 때,
> 먼저 복제해 두고 사본을 고치세요.

## 다른 컴퓨터에서 보기

**같은 계정으로 로그인하면 그대로 따라옵니다.** 따로 하실 일이 없습니다.

집에서 만들고 사무실에서 이어서 작업하거나, 노트북과 데스크톱을 오가며 쓸 수 있습니다.

### 두 곳에서 동시에 고치면요?

**나중에 고친 쪽이 남습니다.** 같은 기획서를 두 컴퓨터에서 동시에 열어 두고 각각
다른 부분을 고치면 마지막 편집만 남을 수 있으니, 한 번에 한 곳에서 작업하시는 편이 안전합니다.

### 한 곳에서 지우면요?

**다른 컴퓨터에서도 사라집니다.** 되살아나지 않습니다.

---

## 파일로 백업하기

계정에 저장되지만, 중요한 기획서는 파일로도 받아 두시면 마음이 편합니다.

**내보내기** → **플랜 JSON** 을 내려받으면 기획서 전체가 파일 하나에 담깁니다.
카드의 `⋮` → `JSON 내보내기` 로도 됩니다.

### 되돌리기

홈의 **`플랜 가져오기`** 를 누르고 그 파일을 고르면 됩니다.
**파일을 화면에 끌어다 놓아도** 됩니다. 여러 개를 한 번에 놓아도 됩니다.

가져온 기획서는 **새 기획서로 추가**됩니다. 기존 것을 덮어쓰지 않습니다.

---

## 로그인 전에 만든 기획서

로그인 기능이 생기기 전에 만들어 둔 기획서가 있다면, 처음 로그인할 때 화면 위에
안내가 뜹니다.

> 로그인 전에 이 브라우저에서 만든 플랜이 **N개** 있습니다.
> `내 계정으로 가져오기`  `버리기`

**`내 계정으로 가져오기`** 를 누르면 계정으로 올라가고, 그때부터 다른 컴퓨터에서도 보입니다.

누르기 전까지는 올라가지 않습니다. 한 컴퓨터를 여러 사람이 나눠 쓰는 경우에
남의 기획서가 내 계정으로 딸려 들어가면 안 되기 때문입니다.

> `버리기` 는 되돌릴 수 없습니다. 헷갈리면 그냥 두세요. 안내는 사라지지 않습니다.

---

## 로그아웃하면 기획서가 안 보여요

**정상입니다.** 기획서는 계정에 있고, 이 컴퓨터에 있던 사본만 지운 것입니다.
**같은 계정으로 다시 로그인하면 그대로 돌아옵니다.**

한 컴퓨터를 여러 사람이 쓸 때 앞사람 기획서가 뒷사람에게 보이지 않게 하려는 것입니다.
