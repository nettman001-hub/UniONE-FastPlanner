# 7. 점검하고 내보내기

## 점검 — 정합성 검사

개요 화면의 **정합성 검사**가 문서끼리 안 맞는 곳을 자동으로 찾아 줍니다.
사람 눈으로는 잘 안 보이는 구멍들입니다.

| 등급 | 뜻 | 어떻게 |
| --- | --- | --- |
| **오류** | 참조가 깨져 문서가 성립하지 않음 | 반드시 고치세요 |
| **경고** | 논리적으로 빠진 부분 | 개발 넘기기 전에 채우세요 |
| **제안** | 있으면 더 좋은 것 | 여유가 되면 |

### 자주 나오는 지적과 해결

| 지적 | 무슨 뜻 | 어디서 고치나 |
| --- | --- | --- |
| 화면에 배치되지 않은 기능 | 만들기로 했는데 들어갈 화면이 없습니다 | 정보구조도 → 해당 화면 → `상세 기능 연결` 체크 |
| 하위 기능이 없는 요구사항 | 필요하다고만 하고 어떻게 풀지 안 정했습니다 | 기능명세서에서 기능 추가 |
| 상세 명세가 없는 필수(P0) 기능 | 꼭 필요한 기능인데 동작을 안 적었습니다 | 기능명세서에서 상세 기능 추가 |
| 인수 조건이 없는 상세 명세 | QA가 무엇을 테스트할지 모릅니다 | 상세 기능 편집창의 `인수 조건` |
| 도달할 수 없는 단계 | 이 단계로 들어오는 화살표가 없습니다 | 유저 플로우에서 연결선 추가 |
| 분기가 하나뿐인 조건 | 실패·거절 경로를 안 그렸습니다 | 유저 플로우에서 갈래 추가 |
| 경로가 중복된 페이지 | 두 화면의 주소가 같습니다 | 정보구조도에서 경로 수정 |
| 아직 플로우에 없는 화면 | 이 화면을 지나는 여정이 없습니다 (`제안` — 안 만들어도 됩니다) | 필요하면 유저 플로우 → `플로우 더 만들기` |

### 고치는 두 가지 방법

지적마다 버튼이 두 개 있습니다.

| 버튼 | 하는 일 |
| --- | --- |
| **`AI로 수정하기`** | 그 지적을 **AI 에이전트에게 그대로 넘깁니다.** 패널이 열리며 바로 요청됩니다 (1 크레딧, 고급 엔진은 2). 버튼 앞의 엔진 단추로 등급을 바꿀 수 있습니다 |
| **`직접 수정`** | 해당 문서 화면으로 이동합니다 |

**`AI로 수정하기`** 가 편한 이유는, 지적에 이미 **어느 항목인지(ID)** 가 들어 있기 때문입니다.
문서에 도착해서 스무 개 넘는 표에서 지적된 항목을 눈으로 찾아낼 필요가 없습니다.

> 기능명세서에서 아래 문제를 고쳐 주세요.
>
> 문제: 상세 명세가 없는 필수 기능
> 이유: 필수(P0) 기능은 개발 착수 전에 상세 명세가 있어야 합니다.
>
> 해당 항목:
> - FN-001 이메일 회원가입
> - FN-002 로그인
>
> 해당 항목만 고치고 나머지는 그대로 두세요. 무엇도 지우지 마세요.

이 요청문이 **대화에 그대로 남습니다.** 결과가 마음에 안 들면 이어서 말로 고치면 됩니다.

지적이 여러 건이면 위쪽 **`전부 AI로 수정하기`** 로 한 번에 시킬 수 있습니다.
하나씩 시키는 것보다 크레딧과 시간이 덜 들고, 앞의 것을 고치다 뒤의 것이 함께 풀리기도 합니다.

### 문서 화면에서도 보입니다

같은 지적이 **다섯 산출물 화면 위쪽에도** 뜹니다 — 프로덕트 요구사항 · 기능명세서 ·
정보구조도 · 유저 플로우 · 와이어프레임. 고치는 자리에서 무엇이 지적됐는지 바로 보이고,
거기서도 `AI로 수정하기` 를 누를 수 있습니다.

> 지적이 없는 화면에는 뜨지 않습니다.

각 지적을 누르면 **해당 문서의 그 자리로 바로 이동**합니다.

### `재생성 필요` 라고 붙은 지적

**항목을 손으로 고쳐서는 풀리지 않고, 그 문서를 다시 만들어야 하는 것**입니다.
앞 단계에서 무언가 늘어났는데 뒷 단계가 아직 그것을 모르는 상태입니다.

> 예: 기능명세서에 기능을 추가했는데 정보구조도와 와이어프레임은
> 그 기능을 모르는 채로 남아 있는 경우

같은 표시가 **정보구조도와 와이어프레임 화면 위쪽에도** 똑같이 뜹니다.
어느 화면에서 보든 뜻은 하나입니다 — **이 문서는 지금 앞 단계보다 뒤처져 있습니다.**

> **유저 플로우에는 붙지 않습니다.** 플로우는 모든 화면을 덮을 필요가 없어서,
> 안 덮인 화면이 있어도 결함이 아니기 때문입니다.
> → [화면 설계 · 몇 개나 만들어야 하나요](./05-screens.md)

> **개발팀에 넘기기 전에 오류와 경고를 0으로 만드세요.** 여기서 잡히는 것들은
> 대부분 개발 중간에 발견되면 일정이 밀리는 종류입니다.

## 되돌릴 지점 만들기 — 버전

개요 화면의 **버전 기록**에서 **`현재 상태 저장`** 을 누르면 지금 상태가 통째로 저장됩니다.

이럴 때 눌러 두세요.

- 문서를 크게 뜯어고치기 전
- `다시 생성` 을 누르기 전
- AI 에이전트에게 큰 작업을 시키기 전

최근 **20개**까지 보관합니다. 복원은 확인을 한 번 거칩니다.

각 문서의 항목마다 말풍선 아이콘으로 메모를 남길 수 있습니다.

혼자 쓸 때는 "여기 나중에 다시 보기" 표시로, 같이 쓸 때는 서로에게 남기는 쪽지로 씁니다.

## 내보내기

왼쪽 메뉴의 **내보내기**에서 완성된 기획서를 밖으로 가져갑니다.

### 어디에 쓸지 먼저 정하세요

| 이럴 때 | 이걸 쓰세요 |
| --- | --- |
| Notion·구글독스에 붙여넣기 | **마크다운** |
| 엑셀로 기능 목록 정리 | **기능명세서 CSV** |
| 개발 견적 요청 | 마크다운 + 기능명세서 CSV |
| **Cursor·Claude Code 같은 AI 개발 도구에 물리기** | **에이전트 번들** |
| **구글 스티치·Figma 같은 AI 디자인 도구에 물리기** | **디자인 도구로 넘기기** |
| 백업 / 다른 곳으로 옮기기 | **플랜 JSON** |
| 그냥 보여 주기만 | **보기 전용 링크** |
| PDF 로 저장 | `문서 보기` → `인쇄` |

### 파일 6종

| 형식 | 내용 |
| --- | --- |
| **마크다운** | 문서 전체를 글로. Notion·GitHub 에 그대로 붙습니다 |
| **기능명세서 CSV** | 요구사항–기능을 행으로 펼친 표. 엑셀에서 바로 열립니다 |
| **정보구조도 CSV** | 화면 목록 |
| **플랜 JSON** | 기획서 전체 (백업·이동용) |
| **에이전트 번들** | AI 개발 도구용 |
| **Mermaid 플로우** | 유저 플로우 전체를 코드로 |

위쪽에서 **어떤 문서를 포함할지** 고를 수 있습니다. 이 선택은 마크다운과 문서 보기에
반영됩니다. CSV·JSON·번들은 항상 전체를 담습니다.

> CSV 는 엑셀에서 한글이 안 깨지도록 처리되어 있습니다. 그냥 두 번 누르면 열립니다.

### 그림으로 받기

와이어프레임은 **SVG** 또는 **PNG** 로 받을 수 있습니다.
`전체 PNG 내려받기` 를 누르면 모든 화면을 한 번에 저장합니다.

- **SVG** — 크기를 키워도 안 깨집니다. 디자이너에게 넘길 때
- **PNG** — 슬라이드·문서에 넣을 때

유저 플로우 그림은 **유저 플로우 화면**에서 받습니다.

## AI 개발 도구에 물리기

**에이전트 번들**은 Cursor, Claude Code 같은 AI 코딩 도구가 읽기 좋게 정리한 파일입니다.
기능과 화면의 관계가 이름까지 펼쳐져 있어서, 도구가 다른 문서를 열어보지 않아도 됩니다.

1. **에이전트 번들**을 내려받습니다. (예: `plan-bundle.json`)
2. 개발 프로젝트 폴더에 넣습니다.
3. AI 도구에게 이렇게 시킵니다.

```
plan-bundle.json 을 읽고 informationArchitecture 의 각 페이지를 라우트로,
requirements[].features[].specifications 를 구현 단위로 삼아 작업 계획을 세워줘.
```

상세 기능의 **기본 흐름**이 구현 기준이 되고, **인수 조건**이 테스트 기준이 됩니다.
그래서 [4. 요구사항과 기능 정리](./04-requirements.md) 에서 이 두 칸을 잘 채워 두면
결과가 확연히 달라집니다.

## 디자인 도구로 넘기기

와이어프레임까지 다 만들었으면 디자인 도구로 넘길 차례입니다. 내보내기 화면에
**두 개의 카드로 나뉘어** 있습니다.

| 카드 | 준비물 | 결과 |
| --- | --- | --- |
| **자동(UI 먼저 만들기) - 바로 만들기 · 스티치** | 스티치 연결 한 번 | 여기서 눌러 스티치 계정에 화면이 생깁니다 |
| **자동(UI 먼저 만들기) - 바로 만들기 · UinAI** | 없음 | 여기서 만들고 UniBoard 안에서 엽니다 |
| **수동(UI 먼저 만들기) - 요청문 복사해 붙여 넣기** | 없음 | 요청문을 복사해 도구에 붙여 넣습니다 |

준비물도 결과도 달라서 갈라 두었습니다. 한 자리에 섞어 두면 연결하신 분은 필요
없는 요청문을 지나쳐야 하고, 연결 안 하신 분은 눌러도 안 되는 단추를 먼저
만나게 됩니다.

### 자동(UI 먼저 만들기) - 바로 만들기

자동 카드 위쪽에서 **`스티치에 바로 만들기`**와 **`UinAI로 바로 만들기`** 중 하나를
고릅니다. 화면 선택, 디자인 스킬, 와이어프레임 반영 정도는 어느 쪽에서도 같습니다.

#### 스티치에 바로 만들기

화면을 골라 누르면 **사장님 스티치 계정에 실제 디자인이 생깁니다.** 만들어진
것은 스티치에서 계속 편집하실 수 있습니다. 붙여 넣을 것이 없습니다.

#### UinAI로 바로 만들기

별도 계정을 연결하지 않고 UniBoard의 AI로 화면을 만듭니다. 모델은 **기본 엔진**과
**고급 엔진** 중에서 고릅니다. 완성된 화면은 플랜에 저장되고 각 행의
**`UniBoard에서 열기`**로 안전한 내부 미리보기에서 확인할 수 있습니다.

내부 화면에서는 다음 작업을 할 수 있습니다.

- 데스크톱·모바일 너비로 미리보기
- HTML 보기·내려받기
- UinAI 결과가 포함된 `plan-bundle.json` 받기
- 코딩 에이전트용 지시문 복사

기능·와이어프레임을 고친 뒤에는 기존 결과에 **`업데이트 필요`**가 붙습니다. 해당
화면만 다시 골라 만들면 최신 결과로 교체됩니다.

### 수동(UI 먼저 만들기) - 요청문 복사해 붙여 넣기

화면 이름·기능·역할·블록의 구성 항목·기획 메모를 도구가 알아듣는 문장으로
조립해 두므로, **복사해서 붙여 넣기만** 하면 됩니다. 직접 적으시면 한 화면에
10분씩 걸리고, 적다 보면 빠뜨립니다.

연결이 필요 없어 **어느 도구에나** 쓸 수 있습니다. 스티치를 고르셔도 이 길은
그대로 열려 있고, 결과는 같습니다.

### 스티치 연결하기

자동 카드에서 `스티치에 바로 만들기`를 고르면 연결 칸이 있습니다.
스티치에서 발급받은 API 키를 붙여 넣고 **`연결`** 을 누르세요. 한 번만 하시면 됩니다.

#### API 키는 어디서 받나

연결 칸 옆의 **`키 받는 법`** 을 누르시면 안내가 뜹니다.

> 스티치의 프로필에 스티치설정에서 API키를 받아오세요.

[stitch.withgoogle.com](https://stitch.withgoogle.com) 에 로그인하신 뒤
**프로필 → 스티치 설정**에서 API 키를 발급받아 오시면 됩니다.

| 알아 두실 것 | 내용 |
| --- | --- |
| 어디에 만들어지나 | **사장님 스티치 계정**입니다. 우리 것이 아닙니다 |
| 한 번에 몇 개 | **제한 없습니다.** 화면 하나에 40초 안팎, 고른 수만큼 걸립니다 |
| 붙여 넣은 값 | 암호화해 보관하고 **화면으로 다시 내보내지 않습니다** |
| 끊고 싶으면 | `연결 해제` 를 누르면 지워집니다 |

### 디자인 고르기 — 서비스 전체의 결

화면을 하나씩 만들면 색·글꼴·모서리가 화면마다 달라집니다. 그렇다고 "무슨 색에
무슨 글꼴" 을 직접 적으라면 막막하죠 — 그건 디자이너의 말입니다.

그래서 **자주 쓰는 결을 미리 만들어 두었습니다. 고르기만 하면 됩니다.**

| 스킬 | 어떤 서비스에 |
| --- | --- |
| **깔끔한 기본** | 대부분의 서비스. 여백 넉넉하고 조용합니다 |
| **친근한** | 일반 소비자용 앱. 둥글고 밝게 |
| **업무용 · 정보 밀집** | 관리자 화면, 대시보드. 한 화면에 많이 |
| **커머스** | 물건 파는 화면. 사진과 가격이 먼저 |
| **누구나 쓰기 쉽게** | 어르신·저시력 사용자까지. 글씨 크고 대비 높게 |
| **어두운 화면** | 오래 보는 화면, 미디어·개발자 도구 |

고른 스킬은 **스티치의 디자인 시스템으로 만들어집니다.** 색·글꼴·모서리와 함께
지침 문서가 통째로 들어가고, 이후 만드는 화면이 전부 그것을 따릅니다. 화면마다
"파란색 써 주세요" 를 반복하는 것과는 다릅니다.

`무엇이 정해지나` 를 누르면 그 스킬이 실제로 무엇을 정하는지 볼 수 있습니다.

> `안 고름` 을 고르시면 결을 정하지 않고 스티치에 맡깁니다.

### 모델 고르기

UinAI는 **기본 엔진**과 **고급 엔진** 두 가지입니다. 기본 엔진은 빠르고 화면당
5크레딧, 고급 엔진은 더 촘촘하고 화면당 10크레딧입니다. 실제 모델 이름과 API 키는
서버에서만 관리합니다.

스티치에서는 다음 규칙을 따릅니다.

**목록은 스티치에서 직접 받아 옵니다.** 저쪽이 새 모델을 내면 우리가 고치지
않아도 버튼이 하나 늘어납니다.

| | 언제 쓰나 |
| --- | --- |
| **가벼운 쪽** (처음 선택) | 여러 화면을 한 번에 만들 때. 횟수 여유가 있습니다 |
| **무거운 쪽** | 결과가 더 좋습니다. 대신 **한 달에 쓸 수 있는 횟수가 훨씬 적습니다** |

화면을 여러 개 만들다 보면 무거운 쪽은 금방 바닥납니다. 전체는 가벼운 쪽으로
훑고, **중요한 화면 한둘만 무거운 쪽으로 다시 만드는** 편을 권합니다.

한도에 걸리면 그렇게 알려 드리고, 가벼운 쪽으로 바꾸면 바로 이어 가실 수 있습니다.

### 와이어프레임을 얼마나 지킬지

| | 뜻 |
| --- | --- |
| **`그대로`** (처음 선택) | 적어 둔 항목과 순서를 그대로 씁니다 |
| **`균형`** | 내용은 지키고 여백·정렬·크기는 알아서 다듬습니다 |
| **`자유롭게`** | 내용만 지키고 배치는 더 나은 쪽으로 바꿉니다 |

와이어프레임을 꼼꼼히 그려 두셨다면 `그대로`, 대충 잡아 두고 예쁘게 뽑고 싶으시면
`자유롭게` 가 낫습니다.

> 이건 스티치의 설정이 아니라 **우리가 요청문에 적는 문장**입니다. 스티치에는
> 가중치 같은 조절값이 없어서, 무엇을 더 중히 여기라고 말로 이르는 방식입니다.

> **손그림이나 와이어프레임 이미지를 올려서 만드는 것은 여기서 안 됩니다.**
> 스티치 웹 화면에서만 되는 기능이라, 밖에서 부를 방법이 없습니다. 대신 우리는
> 와이어프레임 블록의 구성 항목을 글로 옮겨 보내므로 그림 없이도 꽤 정확합니다.

만드는 중에 **`멈추기`** 를 누를 수 있습니다. 그때까지 만들어진 화면은 스티치에
그대로 남습니다. 일부만 실패해도 나머지는 계속 만듭니다 — 어느 화면이 안 됐는지
목록에 `실패` 로 표시됩니다.

### 실패한 화면만 다시 만들기

실패한 화면만 다시 골라 누르시면 됩니다. **앞서 만든 프로젝트에 이어서** 만들기
때문에, `스티치에서 열기` 를 누르면 전에 만든 화면과 방금 만든 화면이 한자리에
있습니다.

처음부터 다시 하고 싶으시면 **`새 프로젝트로`** 를 누르세요. 지금까지 만든 것은
스티치에 그대로 남고, 다음 화면부터 새 프로젝트에 만듭니다.

### 만든 화면은 다시 들어와도 표시가 남습니다

내보낸 화면에는 **`완료`** 가 붙고, 눌러서 스티치로 바로 갈 수 있습니다.
나갔다 들어오셔도, 새로고침하셔도 그대로 있습니다.

그래서 다시 들어오시면 **이미 만든 화면은 미리 골라지지 않습니다.**

> 만들 화면을 고르세요. 고른 3개에 약 2분 걸립니다.
> 앞서 만든 프로젝트에 **이어서** 만듭니다. 이미 만든 화면 **7개**는 빼 두었습니다.

그대로 `만들기` 를 누르시면 **남은 것만** 만듭니다. 같은 화면을 두 번 만들지
않으니 사용량이 헛되이 나가지 않습니다. 일부러 다시 만들고 싶으시면 그 화면을
직접 체크하시거나 `전체 선택` 을 누르세요.

| 알아 두실 것 | 내용 |
| --- | --- |
| 어디에 남나 | **이 브라우저에만** 남습니다. 다른 컴퓨터에서는 표시가 안 보입니다 |
| 왜 그런가 | 스티치 프로젝트는 연결한 계정에 딸린 것이라, 플랜을 남에게 넘길 때 따라가면 안 됩니다 |
| 표시가 없어도 | **스티치에는 그대로 있습니다.** `스티치에서 열기` 로 확인하세요 |
| `새 프로젝트로` 를 누르면 | 이 표시도 함께 지워집니다. 그 화면들은 놓아준 프로젝트에 속하기 때문입니다 |

### 만드는 동안 자리를 비우셔도 됩니다

화면 스무 개면 십오 분입니다. **그동안 다른 화면에 다녀오셔도 계속 만듭니다.**
돌아오시면 어디까지 됐는지 그대로 보입니다.

| 해도 되는 것 | 하면 멈추는 것 |
| --- | --- |
| 다른 단계로 이동 · 플랜 목록으로 나가기 · 다른 플랜 열기 | **새로고침** · 창이나 탭 닫기 |

멈추는 쪽을 하시려 하면 브라우저가 한 번 묻습니다. 중간에 멈춰도 **그때까지
만들어진 화면은 스티치에 그대로 남습니다.** 다시 들어와 남은 화면만 고르시면
같은 프로젝트에 이어서 만듭니다.

연결하지 않으셔도 됩니다. 아래 **수동** 카드에서 요청문을 복사해 쓰시는 길은
그대로 열려 있습니다.

### 수동 카드 쓰는 순서

**1. 도구를 고릅니다** — Google Stitch · Claude Design · Figma · v0 · 그 밖의 도구.
고른 도구에 맞게 문장이 조금씩 달라집니다.

**2. `① 먼저 전체 방향부터 잡으세요` 를 먼저 넣으세요.**

화면을 하나씩 만들면 색·글꼴·간격이 화면마다 달라집니다. 이 문장으로 톤을 먼저
정하고 화면별 요청을 이어 가면 결과가 한 벌로 나옵니다.

**3. 화면마다 하나씩 복사해 넣습니다.**

| 표시 | 뜻 |
| --- | --- |
| `PG-001 홈` `복사` | 이 화면의 요청문을 복사합니다 |
| `와이어프레임 없음` | 그림이 없어 기능만으로 만든 요청문입니다. 결과가 얕아집니다 |

**`전체 받기`** 를 누르면 모든 화면의 요청문이 담긴 마크다운 파일을 받습니다.

### Claude Design 으로 넘기기

`Claude Design` 을 고르면 요청문에 **요소 이름을 우리 블록 이름 그대로 쓰라는 지시**가
붙습니다. 저쪽에서 만든 시안을 나중에 코드로 넘길 때 이름이 그대로 이어지게 하려는
것입니다.

| 알아 두실 것 | 내용 |
| --- | --- |
| 어떻게 넘기나 | **요청문을 복사해 붙여 넣습니다.** 스티치처럼 여기서 바로 만들지는 못합니다 |
| 왜 못 하나 | 저쪽은 **사장님 구독 계정으로만** 열립니다. 우리 서버가 대신 눌러 줄 수 없습니다 |
| 필요한 것 | Claude 유료 요금제 |
| 좋은 점 | `① 전체 방향` 을 **디자인 시스템으로 저장해 두면** 다음 화면들이 같은 결로 나옵니다 |

만든 시안은 저쪽 내보내기에서 코드로 받으실 수 있습니다.

### Figma 는 그림을 그대로 읽습니다

Figma 를 고르면 화면마다 **`SVG`** 버튼이 생깁니다. 받은 파일을 Figma 캔버스에
끌어다 놓으면 **편집 가능한 레이어**로 들어갑니다. 설명이 필요하면 요청문을 함께
전달하세요.

### 결과가 얕게 나온다면

와이어프레임의 **구성 항목**을 확인해 보세요. 여기 적힌 것이 그대로 요청문에 들어갑니다.

❌ `콘텐츠 영역`, `버튼 3개` → 도구가 아무 말이나 채웁니다
✅ `전동드릴 · 300m`, `대여 신청하기` → 그대로 화면에 나옵니다

**`링크 만들기`** 를 누르면 주소가 하나 만들어집니다. 그걸 전달하면 받는 사람은
**읽기만** 할 수 있습니다. 로그인도 필요 없습니다.

- 문서 내용이 **링크 안에 통째로 담깁니다.** 서버에 아무것도 저장되지 않습니다.
- 받은 사람은 인쇄 버튼으로 PDF 로 저장할 수 있습니다.
- 기획서가 크면 링크가 매우 길어집니다. **경고가 뜨면 플랜 JSON 파일로 보내세요.**

> 링크를 받은 사람이 고칠 수는 없습니다. 같이 고쳐야 한다면 플랜 JSON 파일을 주고받거나,
> 같은 계정으로 로그인해서 쓰세요.
