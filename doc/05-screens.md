# 5. 화면 설계

앞에서 정한 기능을 **어떤 화면에 넣고, 어떤 순서로 오가고, 화면이 어떻게 생겼는지**
정하는 세 문서입니다.

---

## 정보구조도 (IA)

서비스에 어떤 화면들이 있는지 계층으로 정리하고, **각 화면에 기능을 배치**합니다.

### 세 가지 보기

| 보기 | 이럴 때 |
| --- | --- |
| **트리** | 계층을 보며 편집할 때 (기본) |
| **표** | 화면 목록을 한눈에 훑거나 엑셀로 옮길 때 |
| **사이트맵** | 전체 그림을 보여 줄 때 |

### 트리 보기에서 하는 일

각 줄에서 **화면 이름**과 **경로**를 바로 고칩니다. 유형(페이지·모달·탭·섹션)도 바꿉니다.

| 아이콘 | 하는 일 |
| --- | --- |
| **＋** | 이 화면 아래에 하위 화면 추가 |
| **↑ ↓** | 같은 단계 안에서 순서 이동 |
| **펼침 화살표** | 설명 · 접근 역할 · 기능 연결을 폄 |
| **🗑** | 삭제 (**하위 화면도 함께 지워집니다**) |

### 펼쳤을 때 나오는 것

- **설명** — 이 화면이 무엇을 하는 곳인지
- **접근 역할** — 누가 볼 수 있는 화면인지.
  프로덕트 요구사항의 `사용자 역할` 에 적은 것 중에서 고릅니다.
- **상세 기능 연결** — **여기가 핵심입니다.** 기능명세서에서 만든 기능 중
  이 화면에 들어갈 것을 체크합니다.

> 이미 다른 화면에 들어간 기능은 그 화면 이름이 옆에 표시됩니다.
> 같은 기능을 여러 화면에 넣어도 되지만, 의도한 것인지 한 번 확인하세요.

### 미배치 기능 경고

**어느 화면에도 넣지 않은 기능이 있으면 위쪽에 경고가 뜹니다.**

만들기로 해 놓고 화면에는 없는 기능 — 개발 중에 발견하면 일정이 밀리는 대표적인 구멍입니다.
경고를 누르면 목록이 나오니 하나씩 배치하세요.

> 이 연결이 **정합성 검사**와 **와이어프레임 생성**의 기준이 됩니다.
> 여기를 대충 채우면 뒤가 전부 부실해집니다.

## 유저 플로우

사용자가 화면을 **어떤 순서로 오가는지** 그립니다.
"회원가입 → 프로필 작성 → 첫 매칭" 같은 여정 하나가 플로우 하나입니다.

### 도형이 뜻하는 것

| 도형 | 종류 | 쓰임 |
| --- | --- | --- |
| 둥근 알약 | **시작** | 어디서 시작하는지 |
| 위에 색 띠가 있는 사각형 | **화면** | 정보구조도의 화면과 연결됩니다 |
| 사각형 | **사용자 행동** | 누르기·입력하기 |
| 마름모 | **분기** | 조건에 따라 갈라짐 |
| 평행사변형 | **시스템 처리** | 저장·발송처럼 사용자가 안 보는 일 |
| 둥근 알약 | **종료** | 흐름의 끝 |

### 편집

- 위쪽 탭으로 플로우를 전환합니다.
- 플로우 이름 · 수행 역할 · 설명을 바로 고칩니다.
- 그림에서 도형을 누르면 **오른쪽에 편집창**이 열립니다.
- 도형 편집에서 **연결 화면**을 지정하면 정보구조도의 화면과 이어집니다.
- 아래쪽 연결선 목록에서 출발·도착과 조건 문구(`예`, `아니오` 등)를 바꿉니다.

### 점검 배너

이 화면 위쪽에는 플로우 관련 문제만 모아 보여 줍니다.

| 지적 | 무슨 뜻인가 |
| --- | --- |
| 도달할 수 없는 단계 | 이 단계로 들어오는 화살표가 없습니다 |
| 빠져나갈 수 없는 단계 | 이 단계에서 나가는 화살표가 없습니다 (종료가 아닌데도) |
| 분기가 하나뿐인 조건 | **실패·거절 경로를 안 그린 경우가 대부분입니다** |

> 마지막 항목이 특히 중요합니다. "결제 성공" 만 그리고 "결제 실패" 를 안 그리면,
> 개발 단계에서 그 화면을 아무도 안 만듭니다.

### 그림으로 내보내기

| 버튼 | 결과 |
| --- | --- |
| **SVG** | 크기를 키워도 안 깨집니다. Figma 에 그대로 붙습니다 |
| **PNG** | 2배 해상도 이미지. 슬라이드·문서용 |
| **Mermaid 복사** | 아래 코드를 복사해 Notion·GitHub 에 붙이면 그대로 그려집니다 |

## 와이어프레임

각 화면에 **무엇이 어디에 놓이는지** 대략 그린 그림입니다.
디자인이 아니라 **배치와 내용**을 정하는 단계입니다.

### 만들기

**`AI로 생성`** 을 누르면 **어떤 화면을 그릴지 고르는 창**이 먼저 뜹니다.
기본값은 아직 안 만든 화면 전체입니다.

> **한 번에 10개 이하를 권합니다.** 너무 많이 고르면 결과가 얕아집니다.
> 중요한 화면부터 나눠서 만드세요.

### 화면 구성

| 위치 | 무엇 |
| --- | --- |
| **왼쪽** | 만들어진 화면 목록. `＋ 빈 화면` 으로 직접 만들 수도 있습니다 |
| **가운데** | 미리보기. 모바일 / 데스크톱 전환, 인쇄 |
| **오른쪽** | 블록 편집 |

### 블록

화면은 **블록**을 위에서 아래로 쌓아 만듭니다. 17종이 있습니다.

> 헤더 · 내비게이션 · 히어로 · 검색 · 필터 · 리스트 · 카드 그리드 · 테이블 · 폼 ·
> 상세 정보 · 탭 · 텍스트 · 이미지 · 차트 · 배너 · CTA · 푸터

블록마다 **제목**, **구성 항목**, **기획 메모**를 적습니다.

> **구성 항목에는 실제로 화면에 나올 문구를 적으세요.**
>
> ❌ `콘텐츠 영역`, `버튼 3개`
> ✅ `산책 신청하기`, `프로필 보기`, `신고`
>
> 이렇게 적어 두면 개발자와 디자이너가 되묻지 않고 바로 만들 수 있습니다.
> 와이어프레임에서 가장 시간을 들일 가치가 있는 부분입니다.

블록은 위아래로 순서를 바꾸고 삭제할 수 있으며, 아래쪽에서 새로 추가합니다.
